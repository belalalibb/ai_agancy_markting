# 🔬 تقييم المستودعات الكبرى تفصيلياً (Repository Evaluations)
**تاريخ الفحص:** 28 أكتوبر 2026

## 1. تقييم مشروع Postiz (`gitroomhq/postiz-app`)
- **الترخيص:** AGPL-3.0
- **التقنيات:** TypeScript, Next.js, NestJS, Prisma, PostgreSQL, Redis, Temporal.
- **نقاط القوة:** تغطية ممتازة لمعظم منصات التواصل، ودعم جدولة المحتوى والذكاء الاصطناعي.
- **المخاطر والعوائق:**
  1. ترخيص AGPL-3.0 يفرض كشف الكود المصدري لأي نظام يعدل عليه ويعرضه عبر الشبكة.
  2. اعتماده لا يحل مشكلة تسجيل وتدقيق تطبيقات منصات التواصل الرسمية التي تطلبها Meta و TikTok.
  3. اعتماده كحزمة يفرض ازدواجية قواعد البيانات ونظام المصادقة.
- **التوصية:** **REFERENCE ONLY.** دراسة ملفات المهايئات (Adapters) لمعرفة المتطلبات التقنية للمنصات، مع بناء طبقة مهايئات نظيفة خاصة بالمنظومة بـ Python.

## 2. تقييم مشروع Temporal (`temporalio/temporal`)
- **الترخيص:** MIT (SDK) و Apache-2.0 (Server)
- **التقنيات:** Go (Server), Python (SDK).
- **نقاط القوة:** معيار الصناعة العالمي في التنفيذ المتين (Durable Execution) مع إدارة التراجعات وإشارات الموافقة البشرية واستعادة الحالة التلقائية عند الانهيار.
- **التوصية:** **ADOPT (INFRA).** اعتماده كخادم خلفي مستقل لتشغيل كافة مسارات الحملات التسويقية والأتمتة في المنظومة.

## 3. تقييم مشروع Pydantic AI (`pydantic/pydantic-ai`)
- **الترخيص:** MIT
- **التقنيات:** Python 3.10+, Pydantic v2.
- **نقاط القوة:** كتابة وكلاء الذكاء الاصطناعي بنماذج بيانات منضبطة النوع (Type-safe)، مع وجود تكامل رسمي ومباشر مع Temporal (`pydantic-ai[temporal]`) مما يجعل كل استدعاء للنموذج نشاطاً متيناً ومقاوماً للأعطال.
- **التوصية:** **ADOPT (BASE).** اعتماده كإطار العمل الأساسي لوكلاء الذكاء في المنظومة.

## 5. محكمة المراجع — جولة M3→M4 (2026-10-30، طلب المالك؛ بيانات GitHub API لحظية)

> **المنهج:** لكل مرجع ثلاثة أسئلة: ما الذي يفعله أفضل منا؟ ما تكلفة تبنّيه (ترخيص/تشغيل/تبعيات/تعقيد) مقابل كتابة الجزء الذي نحتاجه؟ ماذا يحدث له بعد سنتين؟ الحكم من أربعة: **ADOPT** (نستخدمه) / **EXTRACT** (نأخذ النمط لا الكود) / **WATCH** (نراقبه بشرط إعادة فتح) / **REJECT**.

### 5-أ. `msitarzewski/agency-agents` — MIT، ~165k نجمة، Shell/Markdown، آخر دفع 2026-10-25
- **ما هو:** مكتبة **برومبتات أدوار** (مصمّم، كاتب، مدير مجتمع Reddit…) بصيغة ملفات Markdown تُحمَّل في وكلاء محادثة. لا كود تنفيذ، لا بوابة، لا حالة.
- **ما يفعله أفضل:** تقسيم «الوكالة» إلى أدوار بسيناريوهات واضحة ولغة تشغيلية؛ مادة ممتازة لتصميم **قوالب البرومبت لكل محرك** (كاتب محتوى عربي، مدير ردود واتساب).
- **التكلفة:** صفر تقنياً؛ الخطر أن نُدخل أدواراً قبل أن تكون لها محركات ومنتج. البرومبتات إنجليزية-أولاً وتفترض نماذج أمريكية كبيرة.
- **الحكم:** **EXTRACT.** نقتبس هيكل «دور = مهمة + حدود + معايير قبول» في `prompts.py` لكل محرك (نسخة عربية-أولاً)، ونثبّت كل برومبت بـ`prompt_version` (D-069). لا تبعية، لا استيراد ملفات.

### 5-ب. `stanfordnlp/dspy` — MIT، ~39k نجمة، Python، نشط يومياً
- **ما هو:** إطار «برمجة لا كتابة برومبتات»: توقيعات (Signatures) + وحدات + **محسِّنات** تُعيد صياغة البرومبت/الأمثلة آلياً مقابل مقياس على مجموعة بيانات.
- **ما يفعله أفضل:** تحسين البرومبت بالقياس لا بالذوق — بالضبط ما تحتاجه حلقة D-069 في مرحلتها الثانية.
- **التكلفة:** يحتاج مجموعة أمثلة ذات حجم ومقياساً موضوعياً (لدينا: معدل الموافقة غير المعدَّلة)؛ يجرّ نموذجه الخاص لنداء المزوّدين (**يجب** تقييده خلف `AIGateway` وإلا خُرق D-068)؛ تغيّر API سريع بين الإصدارات.
- **الحكم:** **WATCH ⇒ ADOPT مشروط** (بند مؤجَّل 13): يُشغَّل **خارج الطلب** كأداة أدمن على مجموعة منقّاة ≥ 200 إشارة/قناة، بموفّر LM مخصَّص يمرّ عبر بوابتنا. لا يدخل مسار الإنتاج أبداً.

### 5-ج. `tensorzero/tensorzero` — Apache-2.0، ~11.7k نجمة، Rust، آخر دفع 2026-06-11
- **ما هو:** بوابة LLM + رصد + تقييم + تحسين في منصة واحدة (Rust gateway + ClickHouse + UI).
- **ما يفعله أفضل:** فكرة **«الملاحظات تعود إلى البوابة»** (feedback API يربط كل استدعاء بإشارة جودة لاحقة) — نفس روح D-069، مُنفَّذة بإحكام؛ وتنوّعات (variants) للبرومبت مع تجارب A/B مدمجة.
- **التكلفة:** ClickHouse إلزامي (ثقيل لحجمنا؛ F0 يقول PostgreSQL أولاً)، خدمة Rust منفصلة، آخر نشاط قبل 4 أشهر (إشارة حذر على الاستمرارية)، يُلغي ملكيتنا للعقد.
- **الحكم:** **EXTRACT.** نأخذ نمطين: (1) `feedback(inference_id, metric, value)` ⇒ عندنا `learning_signals(revision_id, signal, value)`؛ (2) `variant` ⇒ عندنا `prompt_version`. لا نتبنّى المنصة.

### 5-د. `david-lev/pywa` — MIT، ~600 نجمة، Python، آخر دفع 2026-10-26
- **ما هو:** مكتبة Python لـWhatsApp Cloud API: Webhook موقَّع، قوالب، وسائط، أزرار/قوائم، تكامل FastAPI أصيل، مكتوبة بأنواع صارمة.
- **ما يفعله أفضل:** يختصر ~70% من كود M6 (تحليل Webhook، التحقق من التوقيع، بناء القوالب التفاعلية) بمكتبة مختبَرة تتبع إصدارات Graph.
- **التكلفة:** تبعية خارجية صغيرة بمؤلف واحد أساسي (خطر الحافلة؛ لكن MIT + كود بسيط يمكن تثبيته/تفريعه)؛ يجب أن يمرّ عبر `meta_client`-مثيل لا بجوار D-064 (الأسرار في Bearer/الجسم).
- **الحكم:** **ADOPT (COMPONENT) في M6** بشرطين: تثبيت الإصدار + اختبار تقاطع يُثبت أن `appsecret_proof`/التوقيع ومسار الأسرار متوافقان مع D-064؛ ويُضاف إلى `OPEN_SOURCE_CATALOG`.

### 5-هـ. Temporal مقابل «حلقة PostgreSQL» للجدولة (قرار M4 — SPRINT-07)
| المعيار | Temporal (D-057) | حلقة PG (`SELECT … FOR UPDATE SKIP LOCKED` + مهلة قيادة) |
|---|---|---|
| ما يحلّه | تنفيذ متين لمسارات طويلة، إشارات، تراجعات، إعادة محاولة بسياسات | «انشر هذا في الساعة X مرة واحدة» + إعادة محاولة محدودة |
| التكلفة التشغيلية الآن | خادم Go + قاعدة بيانات له + SDK + worker منفصل = حاويتان جديدتان قبل أول عميل | **صفر** مكوّنات جديدة؛ جدول `publish_jobs` + عامل `asyncio` داخل العملية |
| الاختبار | يحتاج خادم اختبار/time-skipping | PG حقيقية (لدينا) + حقن `now` |
| المخاطر | تعقيد مبكر، منحنى تعلّم، تبعية ثالثة قبل V1 | تعدد النسخ يحتاج `SKIP LOCKED` (مُتاح) ؛ لا سير عمل معقّد |
| قابلية الانتقال | — | واجهة `Scheduler` Protocol ⇒ `PostgresScheduler` الآن، `TemporalScheduler` حين يظهر أول مسار متعدد الخطوات (حملة) |
- **الحكم:** **M4 يُبنى على حلقة PG خلف `Scheduler` Protocol؛ Temporal يبقى ADOPT مؤجَّلاً** إلى أول حالة استخدام حقيقية لمسار طويل (حملة متعددة المنشورات/موافقات متسلسلة — متوقَّع M7/ما بعد V1). هذا **ليس** تراجعاً عن D-057 بل تأجيل تنفيذه حتى يستحقّ كلفته.
