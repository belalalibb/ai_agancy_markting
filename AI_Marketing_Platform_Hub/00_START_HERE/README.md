## 🎯 1. الغرض من هذا المجلد المركزي

يمثل هذا المجلد (`AI_Marketing_Platform_Hub`) نقطة الارتكاز المركزية والشاملة لجميع جهود التخطيط، والبحث، والمعمارية التقنية، والتنفيذ البرمجي التي تمت على مدار مسيرة تطوير **منظومة التسويق الإلكتروني بالذكاء الاصطناعي (AI Marketing & Growth Platform)** بمختلف مسمياتها ومراحلها السابقة (SocialAI Pro, BrandMind AI, Marketing SaaS, QEVION, AI Growth OS).

تم إعداد هذا المرجع لحل مشكلة التشتت البرمجي والتوثيقي، وتجميع المعرفة المتراكمة عبر مئات الوثائق وآلاف أسطر الكود البرمجي في بنية واحدة منظمة، قائمة على الأدلة الفعلية، تفصل بين:
1. **ما تم إنجازه والتحقق منه برمجياً واختبارياً.**
2. **ما نُفذ جزئياً ويحتوي على أصول برمجية قابلة للاستخدام.**
3. **ما تم التخطيط له والموافقة على قراراته المعمارية ولم يبدأ برمجياً.**
4. **ما كان مجرد مقترحات أو تجارب أولية تحتاج إلى تقييم وحسم.**

## 🧭 2. المبادئ الحاكمة للمشروع (Constitutional Principles)

تعتمد المنظومة على مبادئ معمارية واستراتيجية صارمة جرى اعتمادها وتثبيتها عبر مسار المشروع (القرارات الحاكمة D-001 إلى D-055 ودستور العائلة F0):

1. **Static Core, Dynamic Intelligence, Additive Capabilities, Governed Evolution:**
   القلب البرمجي المشترك للمنظومة (Core) صغير ومستقر ولا يحتوي على منطق تسويقي محدد. الذكاء التسويقي، ومحركات الصوت، والفيديو، وتوليد المحتوى، وتحليل البيانات هي قدرات مضافة (Capabilities) تُركّب فوق الأساس عبر عقود برمجية موحدة.
2. **الأدلة قبل الادعاءات (Evidence Before Claims):**
   لا نعتبر أي ميزة مكتملة لمجرد وجود كود أو وثيقة خطة. الاكتمال يتطلب اختبارات ناجحة، وبيئات تشغيل، وأدلة ملموسة.
3. **إعادة استخدام المحركات المفتوحة المصدر المعتمدة وتجنب فخ الـ AGPL:**
   الاعتماد على المحركات الناضجة المصرح بها بتراخيص متساهلة (MIT / Apache-2.0 / BSD) لعزل البنية التحتية، وبناء ميزة التمايز التنافسي (العقل التسويقي والربط الذكي) داخلياً، مع الامتناع التام عن دمج مشاريع AGPL داخل الكود التجاري المغلق.
4. **احترام قيود منصات التواصل الاجتماعي الرسمية:**
   إدراك أن عنق الزجاجة الحقيقي في النشر ليس برمجياً، بل هو الامتثال الإجرائي والتراخيص الرسمية لواجهات المنصات (Meta Graph API Advanced Access, TikTok Content Posting Audit, LinkedIn Version Sunsets, و تسعير منصة X).
5. **النموذج الاقتصادي المستدام (Unit Economics First):**
   المنصة تبيع القيمة والتنظيم والأتمتة، ولا تبيع الـ Tokens أو ثواني الفيديو بالخسارة. دعم نموذج (BYOK - Bring Your Own Key) للخدمات المكلفة لحماية هوامش أرباح المنصة (76% - 97%).

## 🗂️ 3. الهيكل التنظيمي للمركز المعرفي

تم تنظيم المركز المعرفي إلى 13 قسماً رئيسياً مترابطاً:

```text
AI_Marketing_Platform_Hub/
├── 00_START_HERE/              # نقطة البداية، الفهرس الشامل، وحالة المشروع التنفيذية
├── 01_PROJECT_DISCOVERY/       # جرد الأصول السابقة، تدقيق الأعمال، الفجوات والتعارضات
├── 02_REQUIREMENTS_AND_VISION/ # الرؤية، المشكلة، العملاء، حالات الاستخدام، والمتطلبات
├── 03_EXISTING_PROGRESS/       # تفصيل الإنجاز: المكتمل، قيد التنفيذ، المؤجل، والأصول
├── 04_ARCHITECTURE_AND_DESIGN/ # المعمارية التفصيلية للمنظومة، المحركات E1-E12، والقرارات
├── 05_OPEN_SOURCE_RESEARCH/    # كتالوج المصادر المفتوحة المعتمدة، تقييم التراخيص والمنافسين
├── 06_PRODUCT_PLANNING/        # نطاق المنتج، تعريف النسخة الأولى (MVP)، وخارطة الطريق
├── 07_EXECUTION_AND_TESTING/   # خطة التنفيذ المرحلية، سجل المهام (Backlog)، واستراتيجية الاختبار
├── 08_SECURITY_AND_OPERATIONS/ # الأمان، حماية البيانات والأسرار، المراقبة، والتكاليف
├── 09_BUSINESS_AND_GO_TO_MARKET/# نموذج العمل، التسعير، التسويق الذاتي، ومؤشرات النجاح
├── 10_DECISIONS_AND_HISTORY/   # سجل القرارات الشامل (D-001 -> D-055)، والتاريخ التراكمي
├── 11_HANDOVER/                # دليل تسليم المهندسين ووكلاء الذكاء الاصطناعي، والأسئلة المفتوحة
└── 12_ARCHIVE_INDEX/           # فهرس وإحالات الملفات والمستودعات التاريخية الأصلية
```
